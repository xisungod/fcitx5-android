# AXiang 1.2-touch.7 首轮评测、查询恢复与候选细节

本版针对 touch.6 手机测试暴露出的三个可直接改善的问题：删改后原本失败的首轮输入被排除出评分；备选查询超时后当前组合不再恢复；候选注释与纠错星号字号过大。原 Rime 1.16.1、全部 350 个资产与 28 个 ARM64 库沿用 touch.6 的实际字节。

## 安装

版本为 `1.2-touch.7`，版本号 `7`，应用名称仍为“AXiang 触点测试2”。包名与持久测试签名和 touch.2–touch.6 相同，可以覆盖安装并保留设置与用户词库。已有偏好同样保留。

## 测试要看什么

先按自然速度输入，观察候选右侧拼音注释与 `*` 标记：它们应比主要汉字更小、间距更紧凑；整项候选仍保持原有点击范围。输入 `nihaoa`、`nishia` 等普通拼音和故意邻键误按时，原始候选都应保留。

打字测试报告将首轮结果与最终完成结果分开统计。首轮快照在后续退格、选词和重打之前保留，不能因为最终纠正就把早期失败抹掉。目标拼音、可靠触点对齐与排除原因需要一起看，未可靠标注的触点不能拿来自动训练个人模型。报告记录触摸的手指编号、按下/抬起时刻与派发顺序，帮助区分落点偏移和双指字母颠倒。

首选/前三命中注明完整候选快照的评分分母；首次退格、上屏或明确停止前的原始按键另列，提前停止时不会把尚未输入的尾部计为漏字。退格负担按发生退格的题目统计平均次数，不把“每句平均退格”声称为“每个错误的成本”。单次备选查询还拆出总耗时、加载、初始化、原生查词与缓存状态，便于判断冷启动和查询本身分别花了多久。

设置中的触点查询状态用于查看实际 Rime 版本、查询库状态与最近结果。正常无候选、耗时超限、库加载失败和接口失败是不同情况。报告会提醒查询不可用，不能把立即失败的低耗时当作性能改善。

查询恢复保留时间预算与有限重试，降低重复建立实例的开销。它不将原生 Rime 调用移到独立线程，也不声称一次同步查询可以被中途取消。首选排序默认开启，但需同时满足触点与候选证据，保护正确全拼、简拼和正在输入的前缀，并保留原串候选；不能仅凭 `zj`、`xh` 等简拼组合就改字母。

首选提升范围很窄：需要已有可靠校准、空间证据明显支持邻键，且原串没有受保护的完整全拼、混合简拼或未完成前缀解释；建议也只从原候选栏靠前位置提升。第 5、17 句的 `zj`、`xh` 可作为简拼，不能保证这两句自动排第一。公开合成回归与正确输入对照只能验证门槛逻辑，不能证明真实误纠率低于千分之一。

个人化开关默认开启，将已有的合格逐键落点配置用于 DOWN 坐标的空间评分与备选排序；没有足够可靠样本时不调整空间评分。键帽位置保持原布局，原始点按字母仍保留。测试结束后，只有主动点击应用校准，才使用目标已知、可靠对齐并经确认的样本建立限幅配置，也可一键重置。不会从日常候选猜测自动训练，亦不默认收集独立诊断日志。此次不开放自动改字母。

## 发行证据

`scripts/prepare-axiang-touch7-delivery.py` 固定公开 touch.6 APK 的 SHA256 与大小，核对全部 350 个资产和 28 个库与新 APK 逐字节一致。探测库仍从冻结源码重新编译；即使其字节不变，构建来源要绑定当前 Kotlin 包装代码并重新执行查询验证。允许 `--reuse-prebuilt` 只读复用已核验的本地输入，但必须检查每项内容，不能直接信任旧 manifest。

最终交付要求干净冻结提交、真实 DEX 源码标记、真实完整 JUnit XML、Rime 1.16.1 主机回归，以及 APK 实际 ARM64 库在 Android bionic 上的成功查询和隔离证据。签名与 touch.6 相同，版本号提高，APK 满足 16 KiB 对齐且不增加网络权限。

ARM 执行采用 QEMU 与严格 FakeJNI 适配器，主测试引擎只在一次性用户目录正常部署公开数据，再验证独立只读查询不会改变输入、光标、候选、用户文件或上屏文字。这不是 ART、完整手机界面、真实安装或手机性能测试。

所有测试计数、源码身份与 APK SHA256 以发行附带的校验文件为准。真实诊断日志与用户报告保留本机，不包含在公开发行材料中。主机与模拟运行不能保证手机上的首选命中或延迟；应结合首轮命中、退格负担、查询成功/显示/采用与真实手机耗时判断效果。
