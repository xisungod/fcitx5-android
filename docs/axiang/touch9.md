# touch.9：不需要校准的拼音纠错

## 改了什么

- **边缘死区**：“将按键范围扩展至边缘”改为默认开启。此前 A 左侧、L 右侧各半个键宽的空白处按下会被丢弃。
- **拼写搜索**：从“最多改两个、且落点必须在按键边界 6dp 内”改为在所有落点允许的全拼拼写里搜索（按音节自动机构造的格）。落点更深的误触、第三处错误都可以修正。每个字母保留最多三个邻键假设，邻键相对原键的似然低于约 2% 时不再考虑。
- **升首选**：不再依赖个人校准偏移，也不要求该词已在原候选前三。以下情况原输入永远优先：完整全拼、未写完的音节、纯声母简拼。原输入也可读成“音节加声母”时，需要落点贴近边界且优势更大才会升首选。Rime 自己的纠错候选已排第一时不覆盖。
- **联想词时的收起按钮**：联想词占用候选栏时，栏尾显示收起键盘按钮。
- **短信验证码状态页**：补充系统设置提示（荣耀/华为“验证码安全保护”，Android 15 以上的受限制设置）。

## 模拟结果（不是真机数据）

方法：按词频从 rime-ice 基础词库抽词，按键中心加各向同性高斯噪声生成落点，字面字母取落点所在按键。σ 为 9dp 时单键错误率约 4.5%，10.5dp 时约 9%。每组 12000 次。

| 场景 | 改前：打错后自动改对并排首选 | 改后 |
| --- | --- | --- |
| 单词，σ 9dp | 0% | 29% |
| 单词，σ 10.5dp | 0% | 22% |
| 三词连打，σ 9dp | 0% | 35% |
| 三词连打，σ 10.5dp | 0% | 19% |

百分比的分母是“至少打错一个字母的输入”。另有 15–20% 改对但只作为带 `*` 的补充候选（原输入本身是合法拼音时不升首选）。打对的输入没有一次被改动。打对的简拼被误升首选约 0.2–0.3%，原候选紧跟其后。

## 仍未解决

- 打错后恰好是另一个合法拼音（如 nuhao）：只给补充候选，不升首选。需要词级语言模型比较，尚未做。
- 最后一个字母打成辅音（如 nihap）：会被当作未写完的音节，不纠正。
- 超过 32 个字母的输入不查询备选。
- 真机落点分布未知，以上阈值来自模拟。

## 构建状态

合并时 Android 侧改动（工具栏、键盘、设置、字符串）尚未经过完整构建，界面测试也未运行。touch.9 不改原生代码、词库和模型，测试包由 Pull Request 流程构建：按 touch.2 至 touch.8 的做法，逐字节复用已发布 touch.8.2.2 包内的 351 个资源文件和 29 个原生库（含 `libaxiangtouch.so`），只编译当前的 Kotlin 代码和资源（`scripts/prepare-axiang-touch9-build.py`）。测试包由 GitHub Actions 的调试证书签名，包名为 `org.fcitx.fcitx5.android.axiang.touch9`，与 touch.8.2.2 并存安装，不能覆盖升级。原先从源码完整构建的流程保留为手动的 `full-source-build.yml`，它目前在主机 Rime 整句纠错检查处失败，尚未修复。
