# AXiang 1.2-touch.4 边界候选与处理时间测试

本版在 touch.3 的内置打字测试上优化边界候选评分，把触点搜索移出按键输入队列，并补充 `*` 建议的效果及分段耗时记录。目标是减少边界歧义造成的选词负担、找到手机上的处理热点。源码和本地测试通过仍不能证明手机准确率或延迟已经达标，需要用同组题目继续对照。

## 安装与测试

版本为 `1.2-touch.4`，版本号为 `4`。应用名称继续为“AXiang 触点测试2”，包名与持久测试签名保持不变，可直接覆盖已安装的 touch.2 / touch.3 并保留它的设置与词库。原 AXiang、touch.1 和诊断包仍是独立应用。

打开 AXiang 设置首页的“打字测试”，选择 **5 句快速测试**；比较上一轮完整报告时选 **20 句完整测试**。使用 AXiang 中文全拼，按照题目给出的拼音输入整句，再点候选上屏。按平时速度和握持方式打；出现错误可以自然退格或选择候选，不要为提高分数刻意放慢或按准。文字上屏后点“完成这句”，再点“下一句”；最后查看结果并导出 JSON 报告。不需要开启独立诊断日志。

拼音提示默认显示，不输入声调或标点；“绿色的旅行”用 `v` 表示 `ü`。旋转屏幕或重建页面时保留已完成题目，未完成题目重新开始，并记录丢弃次数，避免混合两种布局的输入。

## 输入行为的边界

“双指快打顺序（实验）”“触点候选纠错（实验）”延续默认开启；升级时保留用户先前改过的设置。带 `*` 的建议仍需明确点选，原始拼音与原 Rime 候选数组、分页和选择索引保留。普通水平候选栏第一位保持原 Rime 首选，不自动替换。若建议支持的词原本在 Rime 第二或第三位，显示层可把它放到第二个位置并避免重复文字；若是原前三之外的词或新词，则接在原前三之后，原列表不足三个时接在已有候选后面，不让未知建议挤走原前三集合。空原列表不会凭建议生成首选。只读查询的最优整段候选若与原首选相同，这次完全不提供建议，不继续挑选后面的候选。浮窗与展开候选列表延续原列表，本版没有把它们一并重排。自动边界改判、旧的按键直接纠正、个人化习惯学习和独立诊断日志仍默认关闭。

触点搜索改为读取不可变快照，在独立计算工作线程评分；新按键、编辑框或输入状态变化会令旧结果失效，过期结果不会回写当前输入。评分缓存重复的拼音概率与缺失证据，不再用单个字母概率低于 0.06 直接拒绝整条备选；稀有字母作为概率代价参与完整路径评分，仍要求模型证据和原有保守展示阈值。这些是本地模型启发式分数，不是已校准的用户意图概率；评分高仍可能对应错误的汉字，所以显示位置要结合原 Rime 排名并保留原前三。

本版没有把建议升级成自动改字母，没有自动调整键位、增加漏字/多字/交换纠错，也没有新增神经模型。原有明确滑动选键与双指输出顺序规则延续既有行为。每次最多一条备选拼写送到只读 Rime 查询；查询仍在现有输入线程内串行运行，本版没有引入独立 Rime 工作线程。独立计算线程只处理触点搜索，不跨线程操作 Rime 会话、词库或当前输入。

## 报告的比较口径

原有指标继续采用 touch.3 的口径：首次完整、可评分全拼的编辑率和相邻键替换率；首次完整拼音对应的原 Rime 第一、前三候选命中率；退格次数除以实际字母数；已保留有效单键样本的处理时间 p50、p95 和最大值。后续退格重打或选对词不会覆盖早先的候选快照。第一、前三候选不包含独立的 `*` 建议。

提前退格的前缀、简拼或混合输入、分段上屏、外部输入、缺失记录、多解对齐等会使部分指标无法评分。报告显示可评分分母和排除原因；未评分不等于零错误或成功。每题只贡献一个首次候选样本，短测试不能证明误纠率低于千分之一。

本版报告格式为 `axiang-typing-test-v2`，保留 v1 既有字段，另外记录建议的生成、拒绝、发布、显示、选择和处理结果。同一个提供 token、同种事件去重；流水线次数用于理解建议走到哪一步。这里的“显示”是可见布局槽位的回调，不是屏幕真正呈现的帧。

建议命中率的分母是可评分的完整整句“提供事件”，不是题目数；只纳入明确全拼、目标有效、没有先前分段上屏、原串长度与目标一致且候选非空的记录。同一题可能有多次合格提供。选择处理成功率只统计明确已返回成功或失败的处理结果，未知结果排除；处理成功表示选词事务完成，不等于选中了目标文字，目标选择正确率另行统计。普通中间拼音、局部候选或过期建议不会自动算作整句成功，展示也不代表用户接受。

各阶段耗时样本和建议事件限量保留，超过上限会显式记录省略数量，并在结果页面提示；省略记录不当成零耗时或成功。原候选排名与搜索路径数只用于解释，不是目标真值或模型可靠率。

按键总体时间继续使用 `enqueue_to_key_action_completion_ns`，包含入队后的队列等待及回调处理。搜索移出队列后，脱离按键回调运行的计算与后续查询并不全部包含在这个指标中；它下降可以说明按键回调更早完成，不能单独证明补充候选更早出现或端到端延迟达标。新增分段记录分别测量 `send_key_ns`、`touch_search_ns` 和 `alternative_query_ns`，帮助区分原 Rime 送键、触点搜索和只读查询的热点。这些统计不是屏幕绘制时间、触摸至光效时间或触摸至上屏的完整延迟。分段的 p95 不能直接相加，也不能与总体 p95 相减来推算某个单独阶段的开销。异步任务、队列和测试快照仍可能影响总体样本。

另增 `enqueue_to_offer_publish_ns`（OfferReady），用同一按键入队回执计时，直到对应建议实际发布到 UI 数据流，覆盖既有 35 ms 去抖、前后队列等待、搜索与只读查询的整段过程。只有实际发布且仍属于当前测试代次的提供 token 才记录，取消、拒绝或过期建议不按零耗时计入，也不能据这个指标得知失败查询等了多久。这个样本与前三个阶段重叠，不能相加。它可以帮助判断是否只是按键回调变短、建议仍迟到；终点仍是数据发布而非屏幕呈现，不证明实际帧延迟。对照时应同时看建议数量、未提供原因、回调与 OfferReady 时长，避免只报较小的一个指标。

## 数据与个人化

只在明确开始的应用内专用测试输入框采集当前题目；离开页面、切换编辑框或结束后停止。普通聊天、密码框及其它应用不进入题目报告。报告在本机应用私有、排除系统备份的目录保存，最多最近三份，每份上限 512 KiB；导出使用系统文件保存，分享由用户主动决定。清除本机报告不会删除已导出的副本。

已知目标句不代表每次触摸的意图都可确定。当前校准样本仍要求输入、选词及触点能够可靠对齐；没有把这轮报告自动训练成键位模型。个人化需要先评估未命中的边界样本与选择偏差，再离线验证，不从模型猜测中学习真值。

## 如何判断改动是否有效

使用同一组题目，尽量保持布局、键盘大小、方向、握持方式和打字速度一致；交替测试先后，观察可评分覆盖、邻键错误、原候选命中、`*` 建议效果、退格与处理时间。正确输入被误改、候选选择负担和主观手感也必须观察。单个“经常会”只当回归样例，不代表日常准确率。

手机安装、首选命中改善、误纠率门槛、处理 P95 预算和主观手感均须由真实设备报告确认。后续个人化、自动改字母与撤销、多种错误搜索、独立查询线程和神经重排仍应分别验证，不在这一版一并开放。

## 构建与交付核验

`scripts/prepare-axiang-touch4-delivery.py` 固定复用公开 touch.3 APK 的完整 **350 个资源文件与 28 个 ARM64 原生库**，要求全部逐字节一致。本版没有新增或修改模型、词库、语法资源、概率表或原生库。

交付脚本检查实际 APK 包名、版本、持久签名及 16 KiB 对齐，直接读取 DEX 的 `BuildConfig.BUILD_GIT_HASH` 与干净冻结的源码提交比较，汇总全部实际 JUnit XML，并打包可核验报告。源码补丁只包含经过白名单核验的公开源代码与文档，不含个人测试报告、原始诊断日志、预构建二进制或签名密钥。离线工具 `scripts/typing-test-replay/` 使用相同 Kotlin 评分实现进行触点回放，并把候选回放分开；合成夹具可随源码分享，真实输入报告、触点、目标文字、手机候选及逐键输出只留本机。主机计时与单轮固定题目回归不是手机性能或准确率验收，也不会训练模型。缓存命中增加、模型调用减少或按键回调移出搜索都不等于实测速度更快；当前未通过真实手机数据确认性能改善。

实际测试数、APK 校验值及源码身份以发行附带的 `build-verification.json`、`unit-test-summary.json`、`source-snapshot.json` 和 `SHA256SUMS.txt` 为准。
