# AXiang 1.2-touch.8.2.1：短信验证码授权与显示

本版修复短信验证码的权限衔接、接收生命周期，以及联想条遮挡验证码的问题，可覆盖 touch.8.2 安装。

## 权限与接收

设置项改名为“识别新短信验证码”，默认开启。首次打开 AXiang 或显示键盘时，主动请求接收短信的系统权限；后台启动和接收广播不会弹出授权界面。覆盖旧版后，第一次前台使用也会应用一次本次要求的开启默认值，以免旧版授权失败留下的关闭状态使功能一直不可用；此后用户手动关闭会保留，不会反复自动开启或弹窗。

授权失败时，不再只把开关关回去；界面会说明尚未取得权限，并提供系统应用权限入口。通过该入口完成授权后，继续完成用户本次开启操作。拒绝授权后自动请求不会重复，之后可以在设置中手动重试。应用无法绕过系统或安装器对短信权限的限制；系统不允许授权时，可以复制短信，使用现有的复制内容验证码提示。

接收器改为系统清单中的短信接收器，默认禁用，仅在用户开启且权限已授予时启用。授权、开关变化、应用启动和从系统设置返回时同步状态；移除输入法服务内的重复动态接收。接收端再次检查开关、权限与解锁状态，忽略关闭或撤权后的迟到事件。

该接收方式允许收到新短信时启动应用，无需输入法服务已经运行。不新增读取历史短信权限；开启前已经到达的短信不会被补读。验证码仍只存在进程内存中，五分钟有效，消费后清除；进程在接收后被杀时，内存中的验证码仍可能丢失。

## 显示

有效的短信验证码在空闲工具栏中优先于联想。已有联想让位，迟到的后台联想也不能盖住验证码；正在输入时的正常拼音候选继续正常显示。验证码关闭、关闭提示、点选或过期后，恢复符合条件的联想。开关变化及重新开始输入时重新检查有效缓存，避免打开功能后缓存不显示、关闭后提示仍残留。

## 验证范围

本版重新运行完整应用 JVM 回归，并用合成短信和真实界面组件覆盖接收、权限拒绝、验证码与联想争用等情况。全部原生库、模型、词库和补全索引与 touch.8.2 保持字节一致。原有原生、词库及两百组续接评测证明保留原文件与来源身份，本次不重跑、不改称新结果。

这些检查不代替手机实测。安装器是否允许授予短信权限、厂商系统限制和真实短信送达，需要以手机显示的权限状态为准。Android 17 还可能限制非目标应用接收部分 WebOTP / SMS Retriever 格式验证码短信；本版不新增历史短信读取权限，也不绕过该限制。
