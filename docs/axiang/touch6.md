# AXiang 1.2-touch.6 触点备选查询兼容修复

本版修复 touch.2–touch.5 中触点备选查询被原生版本门禁拒绝的问题。旧探测库要求 Rime 1.12.0，但 APK 实际运行的是 1.16.1；旧主机回归所用的 1.12.0 无法证明手机安装包里这条接口可用。这次保留实际 Rime 与词库，按照它的精确源码及构建补丁重编 `libaxiangtouch.so`，不只修改版本字符串。

同时减少同一次日常 Lua 纠错中的重复原串查询，复用这次调用的有限只读证据。完整原拼音保护、纠错召回与候选顺序保持原规则。公开主机对照检查候选文本、注释、跨度、类型及原生排序字段，并记录查询调用数；主机测得的节省不能直接当作手机整体按键延迟的改善。

## 安装与测试

版本为 `1.2-touch.6`，版本号 `6`，应用名称仍为“AXiang 触点测试2”。包名与持久测试签名和 touch.2–touch.5 相同，可以直接覆盖安装，保留设置与用户词库。

继续按自然速度输入，观察原来容易误按的邻键位置是否出现可点选的 `*` 建议。建议不会主动改写拼音或已经上屏的文字；原串候选保留，touch.5 的完整原拼音优先规则继续适用。正确全拼 `gaileme` 的候选保护仍需和邻键备选的成功显示分别评测。

若做完整打字测试，按照屏幕上的目标全拼输入、选词，再完成当前题目。报告里的备选查询成功、提供、显示和点选分别统计；生成备选不等于查询成功，查询成功也不等于建议被采用。最终文字正确可能包含选词、退格和重打，不能直接当作首轮首选命中。

DOWN 顺序与触点备选默认开启；已有设置保留。自动改字母、自动个人化学习与独立诊断日志没有自动开启。测试报告和真实触点仅保留在本机，由用户主动导出，公开发行材料不包含这些数据。

## 原生兼容性边界

APK 中 `librime.so` 的实际 `RimeGetVersion` 返回 `1.16.1`。核验读取真实 ARM64 ELF 的导出函数、返回值指向和 `RimeApi.get_version` 绑定，不依赖文件名、配置写法或任意版本字符串搜索。

探测代码使用内部 C++ 接口，版本号相同还不足以保证 ABI 一致。构建必须匹配实际引擎的精确源码提交、预构建器对 `Engine` 的 ABI 补丁及实际 Boost 头文件版本。所用源码、补丁、头文件、编译器、引擎、探测库与测试代码的哈希记录在 `native-probe-provenance.json` 和 `native-regression-summary.json`，不得将旧 1.12.0 测试包装成 1.16.1 的证据。

实际 Android 原生执行还发现跨动态库的 RTTI 身份问题：重复或隐藏的模板 RTTI 让配置组件的安全动态类型检查失败。探测库共享实际运行库的组件类型身份，保留动态类型与禁用用户词库的检查，不通过删除隐私检查绕过错误。主机运行成功不能单独覆盖这个 Android 差异，因此发行必须包含真实打包库的成功创建和查询证据。

备选查询继续使用独立的临时输入上下文，不能初始化或重部署全局 Rime，不能改写正在输入的原串、光标、原生候选索引和用户词库。仅查询备选，不执行日常 Lua 纠错、不学习、不直接上屏。成功查询仍受时间预算与候选过滤限制。

## 构建与验证范围

以公开 touch.5 APK 的 SHA256 固定 **350 个资产、28 个 ARM64 原生库**的路径集合，必须真正替换重新编译的 `libaxiangtouch.so`。`librime.so` 与其它 26 个原生库逐字节保持不变。若本次有经单独回归验证的 Lua 修改，只允许更新该 Lua、SOURCE 的单条来源哈希及 descriptor 对应文件和聚合哈希；否则全部 350 个资产保持原字节。

`scripts/prepare-axiang-touch6-delivery.py` 最终核验要求干净冻结源码及真实 DEX 提交标记、实际 APK 包名和版本、持久签名、16 KiB 对齐、精确的原生/资产差异、原生构建来源、完整应用 JUnit XML 与实际 Rime 1.16.1 主机回归。最终 case 数与 APK 哈希以发行附带的校验文件为准。

实际 ARM 原生执行使用 APK 的原始 Rime、重新编译的探测库和公开数据。测试主引擎先完成正常部署，在一次性用户目录生成当前引擎所需的 prism 等缓存，再建立基线快照并查询备选；这些生成文件不替换 APK 的资产。探测本身不能部署、修改基线会话或学习。模拟执行的运行库、探测库、测试数据与生成缓存身份另列在公开运行摘要中。

主机回归、真实 ELF 静态核验或模拟执行不能代替用户手机上的加载、输入准确率和延迟测试。报告中的原引擎同步耗时、备选查询和候选发布耗时需要分别看，不能将各段 P95 相加，也不能把之前立即返回“不可用”的短查询耗时当作修复后的性能。此次没有引入神经网络、个人化模型、新增漏字/多字/交换纠错类型，也没有增加独立 Rime 工作线程。

请将首轮首选/前三命中、退格负担、备选成功率和处理延迟结合起来判断体验。只有真实手机报告才能进一步确认触点建议是否帮助输入，不能在版本发布时保证错误率或延迟已达到目标。
