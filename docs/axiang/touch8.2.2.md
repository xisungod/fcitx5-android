# AXiang 1.2-touch.8.2.2：短信接收状态与授权改进

用户实机反馈 touch.8.2.1 仍未显示验证码，而且短信到达时键盘已打开、功能开关已开启、短信带有验证码关键词。本版不能据此宣称实机问题已经修好；新增可核对的接收状态，区分接收、识别和提示准备，避免把合成短信测试当作手机接收证明。

## 已确认的改进

- 拒绝短信授权不再把用户已开启的功能悄悄改成关闭。系统权限不足时接收器仍禁用；之后从系统权限页允许短信，前台同步即可启用。用户手动关闭仍会保留，不会反复自动弹窗。旧版已经保存的关闭值无法区分来源，仍尊重当前设置。
- 有效短信验证码优先于密码框手动展开的数字行。关闭或过期后恢复原来的数字行；正常拼音候选继续优先显示。
- 新增“短信验证码状态”，显示应用功能、系统权限、实际接收器、只读系统接收检查，以及本次进程收到、识别和准备提示的计数。

计数不含短信正文、发送人或验证码，不保存到文件；进程重新启动后会清零。“准备提示”不代表提示一定已经显示，“收到零条通知”也不单独证明系统拦截。查看或复制状态不会改动授权或接收器；清除计数不会清除验证码。

## 手机上怎样核对

1. 覆盖安装后，打开 AXiang 的“剪贴板 → 短信验证码状态”。核对功能开启、权限允许、接收器启用。
2. 保持键盘打开，获取一条新的验证码短信。
3. 回到“短信验证码状态”，点“复制状态”。状态不含个人短信内容，可以据此继续定位。

收到通知但未匹配，继续查短信格式；已经识别但提示没有准备，继续查界面生命周期；提示已经准备但不可见，继续查显示状态。完全没有新通知，需要结合权限、实际接收器、系统策略及短信格式排查，不能只调整提取规则。

## 验证与系统边界

本版运行完整应用回归，并增加权限拒绝后直接系统授权、手动数字行、数字及密码框、完整 InputView 事件、状态计数与只读检查的合成测试。真实荣耀短信送达仍需实机状态确认。原生库、模型、词库和联想数据与 touch.8.2.1 保持字节一致，已有原生及联想证明按原始来源继承，不改称本次新测。

继续使用接收新短信的权限，不新增收件箱历史读取。当前应用目标 API 36；Android 17 对 WebOTP / SMS Retriever 格式短信的保护仍可能影响接收，这类限制也过滤收件箱查询。不能据此把所有普通验证码短信都认定为被拦截。
