# AXiang 触点测试 1.2-touch.2

安装后启用并切换到“AXiang 触点测试2”，选择中文全拼即可试打。两个新增实验功能默认开启，不需要先设置开关或录诊断日志。本包与 touch.1、原 AXiang 和诊断包并存，设置和用户词库独立；可把布局、尺寸调整到平时习惯的状态。

## 这版改了什么

- **双指快打顺序**：两根手指重叠时，较新的普通中文字母抬起，会先确认更早按下且尚未提交的普通字母。后续较早手指真正抬起不会重复输出。单指仍在抬手时输出，明确滑选、长按、修饰键和弹出键分别处理。
- **触点备选候选**：普通字母原样送入 Rime，保留原始拼音和原候选。共享边界附近的触点会保留少量邻键假设，结合公开拼音字母概率，最多提出一条备选拼写、整串最多替换两处。备选通过只读 Rime 查询补充一个不重复的词语候选，显示为“词语*”。
- **明确点选后上屏**：只有点选带 `*` 的补充候选，才在当前 Rime 输入中重放备选拼写、匹配所选词语并通过正常候选路径提交。查询过程不修改主输入串、光标、候选列表或用户词库。查不到同一完整候选时恢复原始拼音，不强制空格、回车，不另走编辑框直接提交。

可直接自然输入“你好啊”“小姑娘”“经常会”“基本”和日常句子。关注相邻键误输入、双指字母颠倒、退格次数，以及出现 `*` 的候选是否符合原意。`jibgchsnghui` 是回归样例，不能单凭它判断日常准确率。

## 开关与保护

“更多设置 → 输入与候选 → 拼音输入纠错”中，“双指快打顺序（实验）”和“触点候选纠错（实验）”默认开启，可分别关闭作比较。启用触点候选时，旧“拼音触点纠错”的单字母自动改判让位给本模式；不会同时自动改字母和生成另一条备选。

- 快速点按不启用旧自动边界改判。“长按边界调整（实验）”仍默认关闭，明确滑动选键保留。
- 实验只处理中文 Rime 全拼的普通小写字母点按。英文、大写、敏感或密码输入、滑选、弹出键及改动过的预编辑受到保护；键心命中保留原键。
- 当前未完成的末尾片段不贸然纠正，纯首字母简拼保留。暂不新增漏字、多字、交换或模糊音搜索；原 Rime 的既有简拼、词库和组词仍可使用。
- 每次只查询一条备选，停顿约 35 毫秒后才入输入队列；过期结果丢弃。超过 20 毫秒预算的结果不展示，同一组合暂停后续查询。原生查询进行中无法抢占，手机上的实际延迟仍需试用验证。
- 内置约 46 KB 的公开拼音字母概率表，后台加载。证据不足、模型未就绪、布局不符或查询不可用时保留原始输入。没有加入 MiniRBT、Qwen 或其它神经网络。
- 本模式不从自动猜测中学习个人习惯；已有个人化数字统计只有主动启用“按键习惯学习”才参与空间评分。清除入口保留，普通选词和删字重打不会自动训练。当前备选选择也不作为触点偏移标签。

诊断日志默认关闭，密码等敏感输入不采集；只有主动启用才在本机限量记录，并可清空。无需先交诊断数据才能使用实验功能。保存与清空见 [诊断说明](diagnostic-phone-test.md)，旧说明的边界对照流程不等于本版候选实验流程。

概率阈值属于实验实现，公开词频分数不是用户意图的实测概率。本版不是端到端联合解码器，也没有接入已上屏文本的上下文重排。键心误按等情况可能仍出错；真实准确率、误纠率和手机延迟须以试用结果判断。

## 构建与交付核验

本包编译当前 Kotlin 与资源，复用 SHA-256 固定的稳定版 1.2 APK 的原生库和基础资源。349 个基础资源与 27 个基础 ARM64 原生库必须逐字节一致；只增加 `assets/typing/pinyin_touch_model.tsv` 和从公开源码编译的 `lib/arm64-v8a/libaxiangtouch.so`。没有修改基础 Rime 配置、词库、语法模型或资源描述文件。概率表来自已固定版本的公开 Rime Ice 词库，生成脚本不读取个人词库，来源、许可、原文件哈希及平滑参数写在 TSV 注释中。新增原生库使用固定版本 NDK 28.0.13004108 编译；交付工具验证 ARM64 ELF 身份、16 KiB 内存页对齐、源码哈希和所依赖的基础 `librime.so` 哈希。

1.2-touch.2 的包名为 `org.fcitx.fcitx5.android.axiang.touch2`，版本号为 2，应用名称为“AXiang 触点测试2”。它与 touch.1、原 AXiang 和诊断包分别安装，设置与个人词库也分别保存；安装新版不会覆盖或清空 touch.1。使用不同包名是因为公开 touch.1 的 CI 签名密钥没有保存在当前环境，本地已有测试密钥与它不同。touch.2 使用持久保存的测试密钥；后续更新仍需使用同一密钥，以实际签名核验结果为准。

交付目录中的 `build-verification.json`、`unit-test-summary.json`、`model-provenance.json`、`native-provenance.json` 和 `SHA256SUMS.txt` 记录实际 APK 身份、签名、对齐、通过的测试、新增原生库的构建来源及文件哈希。以这些实际输出为准；本地编译和 JVM 测试不等于已经验证手机安装、手感、查询延迟或准确率。
