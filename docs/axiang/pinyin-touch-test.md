# AXiang 触点测试 1.2-touch.1

这是可与原 AXiang、AXiang 诊断并存的独立测试包，名称为“AXiang 触点测试”，包名 `org.fcitx.fcitx5.android.axiang.touch`。设置和用户词库独立；安装后先把布局、尺寸调整到平时使用的状态。

## 开始使用

1. 按应用引导启用并切换到“AXiang 触点测试”，选择中文全拼。
2. 进入“更多设置 → 输入与候选 → 拼音输入纠错”，开启“拼音触点纠错（实验）”。此开关默认关闭，开启后才使用落点和拼音概率共同判定交界处的按键。
3. 先保持“按键习惯学习（实验）”关闭，在普通文本框里按自然速度输入。可试“你好啊”“小姑娘”“经常会”“基本”，也可以直接输入日常句子。
4. 本次按键发生纠正时，候选栏会提供“还原原字母”和“确认纠正字母”。按自己的真实意图选择；继续输入、选词或换输入框后，旧按键的操作入口会失效。这里只处理尚未上屏的最后一次纠正。

想使用个人化时，再开启“按键习惯学习（实验）”。只有你明确点“确认”或“还原”的按键才作为学习依据；自动预测、普通选词和删字重打不会自动成为训练真值。可随时点击同一页面的“清除按键习惯数据”。关闭学习开关后，已有习惯数据也不参与判定。

不需要先录屏或采集诊断才能试用。对比效果时，在同一测试包里只切换“拼音触点纠错（实验）”，保持尺寸、词库与输入速度相近，关注误按、误纠和退格次数。诊断日志仍默认关闭，只有主动开启后才采集；保存与清空方法见 [诊断说明](diagnostic-phone-test.md)。该说明对应旧诊断包的边界对照流程，不适用于本包的长按调整开关。

## 本包的行为与边界

- 快速点按不再使用旧的自动边界改判。可选的“长按边界调整（实验）”默认关闭，开启后也只在按住至少 200 毫秒时允许小幅调整；明确滑动选键保留。
- 字母仍在抬手时提交，没有改变双指提交顺序。
- 仅中文 Rime 全拼的普通字母点按参与实验。明确键心、英文或大写、密码等敏感输入、滑选与弹出键保留原处理；纯首字母简拼受到保护。
- 判定只比较共享边界附近的键；没有把不熟悉的拼音硬判为非法。只调整当前字母，不回改之前的拼音，不改已经上屏的文字。
- 内置约 46 KB 的公开词库字母概率表，后台加载；尚未就绪或证据不足时输出原键。没有加入 MiniRBT、Qwen 或其它神经网络，没有新增 Rime 备选串查询或候选重排。
- 按键习惯只保存有上限的数字统计，按布局和尺寸区分；不保存学习样本中的拼音句子，不上传输入。每个键至少有 8 次明确确认后才逐步使用偏移，幅度受限。

这些规则和概率阈值属于实验实现。公开词频不是用户意图的实测概率，键心附近的误按也不会被这版纠正。实际改善程度、误纠率与手机延迟需要使用结果验证；本说明不承诺准确率或杜绝误输入。

## 构建与交付核验

本包编译当前 Kotlin 与资源，复用 SHA-256 固定的稳定版 1.2 APK 的原生库和基础资源。除 `assets/typing/pinyin_touch_model.tsv` 外，349 个基础资源与 27 个 ARM64 原生库必须逐字节一致。概率表来自已固定版本的公开 Rime Ice 词库，生成脚本不读取个人词库，来源、许可、原文件哈希及平滑参数写在 TSV 注释中。

交付目录中的 `build-verification.json`、`unit-test-summary.json`、`model-provenance.json` 和 `SHA256SUMS.txt` 记录实际 APK 身份、签名、对齐、通过的测试及文件哈希。以这些实际输出为准；本地编译和 JVM 测试不等于已经验证手机安装、手感或准确率。
