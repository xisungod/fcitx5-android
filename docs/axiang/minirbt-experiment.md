# AXiang 本地候选优化实验

本实验在 1.2 稳定发布之后单独提供，用于验证 MiniRBT-H256 是否能改善候选顺序。它仍是实验功能，当前结果不能证明手机上的打字错误率已经降低。

## 开启、下载与关闭

- 默认关闭。正式实验包不包含模型，打开设置或正常打字不会自动下载。
- 在“输入设置 → 实验功能”主动点击“下载语言模型”，下载并校验完成后，再打开“本地候选优化”。下载成功不会自动打开开关。
- 测试包可以内置模型；打开该设置页时只在本机准备模型，开关仍默认关闭。
- 下载界面提供进度、取消和重试。取消或下载失败时继续使用标准候选。
- 关闭开关会恢复标准候选顺序并停止新的模型评分。已经按住候选时先保持其位置，松开后恢复，避免点选过程中候选跳动。
- “删除本地模型”会关闭功能、取消正在进行的下载，并删除本地模型副本。测试包内置资源仍属于 APK，删除副本不会缩小 APK。

模型只保存在应用私有目录 `files/neural_models/minirbt-h256-v1`，不进入用户数据导出或自动备份。重新打开应用时，已开启的功能先验证本地模型；模型缺失或损坏时关闭功能，不自动补下载。

## 本机处理范围

开启后，仅在支持的 Rime 全拼输入中，读取当前输入框内有限的前文并在本机评分。关闭、模型未准备好、密码、邮箱、网址及明确禁止个性化学习的输入框不会进入评分流程。

前文和候选不上传，也不由此实验保存为训练数据。网络权限用于用户主动下载固定模型包，评分路径不会联网。现有离线语音输入继续在本机处理。

## 模型实际承担的工作

采用原始预训练 `hfl/minirbt-h256` 的掩码语言模型（MLM）计算候选的语言分数，再与原候选顺序结合。这次实验没有做输入法专用微调，也没有训练个人模型或实现触摸习惯自适应。

它只重排已经存在的候选，不生成新句子，不修改原始拼音，不自行替换已经上屏的文字。假如正确词句没有进入原候选，模型无法补出该候选。因此“能确定吗”这类候选缺失仍需要拼音解码层另外解决。

当前范围和保护规则：

- 只查看原候选的前 6 项，参与比较的候选必须全部由汉字组成、与原首选字数相同，且长度为 2–8 个汉字。
- 评分异步进行，保留原输入法的顺序权重；一次晋升最多前移 2 个位置，分数差距不足时保持顺序。
- 通常保护原首选。只有原首选明确标为“纠错”，并且存在至少 4 个汉字的已提交前文时，才允许满足更高分差门槛的候选竞争第一位。
- 用户一旦触摸候选，本次候选列表的位置就固定。前文、输入状态或候选变化后，旧评分结果失效。
- 切换输入框、切换输入法、关闭开关、模型删除或评分失败时，标准候选继续可用。

这些限制用于降低通用模型把人名、术语或正确输入改错的机会，不能保证每次建议都正确。

## 已验证与待验证

在宿主机上，真实 PyTorch 与 FP32 ONNX 的掩码评分最大绝对误差为 `0.000175476`，低于设置的 `0.0002` 门槛；Java → JNI → ONNX Runtime C API 的最大误差为 `0.0000243061`。这些验证针对实际模型计算和接口一致性。

本轮 INT8 导出的数值漂移没有通过门槛，因此交付 FP32 版本。不能据“模型更小”假定量化后的效果等同。

宿主机测试中的 FP32 每组候选评分中位耗时约 18.3 ms、最大约 43.8 ms。这不代表 Android 手机的速度。尚需在实机上分别比较开关关闭与开启时的每百字修改次数、误纠正率、首选准确率、候选稳定性、延迟、内存和耗电。通用模型的宿主机分数也不能直接当作端到端纠错率。
