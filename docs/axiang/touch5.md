# AXiang 1.2-touch.5 完整原拼音候选保护

本版修复 Rime 内置 Lua 纠错补充候选可能压过完整原拼音候选的问题。原拼音有完整、标准拼写一致的解释时，让它优先；误拼建议继续保留供点选。本版没有新增自动改字母、键位学习、模型或触摸规则，不宣称所有首选都更准确。

## 安装后怎么感受

版本为 `1.2-touch.5`，版本号为 `5`。包名、持久测试签名与 touch.2 / touch.3 / touch.4 相同，应用名称仍为“AXiang 触点测试2”，可以覆盖升级，保留已有设置与词库。

覆盖安装后，新进程启动时自动同步新的共享 Lua，打开 AXiang 继续正常输入即可。已有设置与词库保留，不需要清空或重新导入。用户自定义 Lua 或 schema 继续使用自己的覆盖规则，本包不删除那些文件。

正常全拼输入，重点看完整原拼音对应的候选是否先出现。公开回归中，`gaileme` 的原拼音结果“改了么”恢复优先，误拼建议“饱了么”等仍在后面；这不代表所有同音词都能自动选中你的本意。遇到纠错结果时仍可点选，拼音栏不会被这段 Lua 主动改写，已经上屏的文字也不会被替换。

## 保守保护的实际条件

检查只读原生 exact translator 的有限候选：必须覆盖整个输入片段，候选给出的标准拼写去掉空格、隔音符后与原拼音完全一致，且质量数值有效。满足时，Lua 产生的额外纠错候选排序低于完整原拼音证据。

这不把所有 `sentence` 类型一律当作正确；简拼展开、拼写别名、自动补全或只有前半段的候选都不能仅靠类型获得完整原拼音保护。额外查询保留真实原生候选的身份、文字、跨度、转换与点选流程，只调整这次独有查询结果的排序质量，不制造直接上屏文本。输入、光标、分页和原生选择索引延续已有流程。

触点 `*` 建议的显示规则沿用 touch.4：空间支持原第二、第三位时可在普通水平栏第二位置提供；原前三之外或新建议留在原前三之后，不挤走原前三集合。浮窗和展开列表保留原 Rime 列表。只读触点探测本身不执行这段 Lua；本次调整发生在日常原生 Rime 候选的 Lua 层，不能把两种建议统计混为一个指标。

## 为什么有些误拼不再自动排第一

误打的字母串有时恰好也是另一个完整合法拼音。例如 `nuhaoa` 同时能解释为“怒号啊”，又可能是想输入“你好啊”。本版保护原串的完整解释，纠错词可能从首选退到第二位，需要点一下。它减少合法输入被误纠的风险，也会降低部分恰巧合法的误拼首选恢复率。

有限的公开主机样本中，14 条误拼目标首选命中由旧版 8 条变为 5 条，前五候选命中仍为 12 条。这是保守策略的取舍，不是手机日常准确率；正确输入对照、简拼、未完成前缀、无完整原拼音证据的误拼必须分别看，不能只报改善的一组。原拼音优先也不保证同音词恰好是用户想要的词。

## 打字测试与版本比较

5 句快速测试、20 句完整测试和 v2 报告继续保留。按题目全拼输入，选词上屏，再点“完成这句”，结束后可导出本机报告。原 Rime 首次候选命中与 `*` 提供、点选统计继续分开；按键回调时间、搜索/查询分段及 OfferReady `enqueue_to_offer_publish_ns` 也保留，后者包含 35 ms 去抖及队列等待，并非屏幕呈现时间。

第 10 题“你现在在哪里”的旧提示漏了一个 `zai`，现改为 `nixianzaizainali`（ni xian zai zai na li）。与 touch.3 / touch.4 报告比较时，应排除或单列这一题，不能把提示修正带来的差异当成纠错算法提升。旧报告不会被自动改写。

测试数据仍只在专用测试输入框采集，报告只存本机，由用户主动导出。独立诊断日志和个人化学习没有自动开启。最终上屏、退格负担、原候选命中、建议命中及其真实分母应一起观察；短测试不能证明千分之一误纠率或手机延迟预算已经达标。

## APK 资产与部署核验

交付以公开 touch.4 APK 为基准，保持 **350 个资产、28 个 ARM64 原生库**的路径集合。允许变化严格为三项：

1. `usr/share/rime-data/lua/xuancai_correction.lua`：使用干净冻结源码中的新脚本。
2. `usr/share/licenses/rime-ice/SOURCE.json`：仅更新该 Lua 的单个 SHA256 来源记录。
3. `descriptor.json`：仅更新 Lua、SOURCE 两个文件哈希及聚合哈希。

其它 347 个资产及全部 28 个原生库逐字节保持 touch.4；字典、索引、schema、预编译 table/prism、语法模型、语音资源和触点概率表没有重建或修改。descriptor 聚合哈希必须改变，否则 Android 资产同步可能跳过更新。新引擎启动时资产管理器据文件哈希同步 Lua、SOURCE；运行时合并 descriptor 随后保存。用户自定义模块和学习词库不在这个覆盖范围内。Lua 的 require 有模块缓存，技术验证以升级后的新引擎进程为准，不能仅凭关闭再打开键盘或热重部署声称新脚本已经加载。

`scripts/prepare-axiang-touch5-delivery.py` 的最终核验要求先从干净冻结提交重新准备，再检查 APK 里的 Lua 字节与该源码一致、三项资产差异精确、SOURCE 其它键值与 descriptor 其它条目保持相同、所有哈希和部署聚合有效。同时验证实际 APK 包名、版本、签名、16 KiB 对齐和 DEX 中的源码提交标记。

## 验证证据与限制

全部 app JVM 测试的实际 XML 数目与结果记录在 `unit-test-summary.json`，用来检查既有输入与界面回归；这些测试不能单独证明 Lua 的原生排序逻辑。

`native-regression-summary.json` 另列真实主机 Rime 1.12 回归的 case 数、结果、测试源码和 Lua/schema/主机 Rime 二进制哈希，以及独立回放摘要。三个常规 suite 使用实际 APK 数据和临时空用户目录的公开合成输入，检查完整原拼音、纠错召回、简拼、未完成前缀、分页、完整和部分候选选择、提交次数与模式状态；旧原生邻键回归也必须在新 Lua 上实际执行。第四个独立 suite 额外使用公开主机 OpenCC 资源，检查下游繁体转换和原生点选流程；该资源没有装入 APK，也不代表手机繁体转换已经验证。对恰好合法的误拼，验收要求原拼音优先、纠错仍在前五，而非一律要求纠错排第一。

主机回归通过不是手机安装、手感、日常准确率或性能验收。APK 里的 ARM64 原生库保持不变，本次原生行为变化来自实际装入的 Lua。公开交付只含代码、合成验证摘要和构建校验文件，不包含真实用户输入报告、触点、日志或签名密钥。实际 app/native 测试数、源码身份及 APK 校验值以发行附带文件为准。
